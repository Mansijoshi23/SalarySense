# SalarySense

**Smart Salary Prediction for Better Career Decisions**

SalarySense is a full-stack web application that estimates an employee's expected annual salary using a trained machine learning regression model. It is built with Python, Flask, and scikit-learn, with a hand-built HTML/CSS/JavaScript frontend — no external AI APIs, no deep learning, and no frontend frameworks.

---

## 1. Project Overview

SalarySense takes a professional's profile — age, education, job title, industry, location, experience, skills, and more — and returns:

- An estimated annual and monthly salary
- A salary range based on the trained model's measured error
- A confidence indicator
- The factors that most influenced the prediction, taken directly from the trained model
- A comparison against the average for similar profiles in the dataset
- Rule-based (non-AI) suggestions for improving earning potential

Every prediction is generated by a real scikit-learn pipeline loaded once at startup — there are no hardcoded or fabricated results anywhere in the app.

## 4. Dataset

**Important note on the dataset:** this project ships with `data/employee_salary.csv`, a **synthetically generated** dataset (see `data/generate_dataset.py`). It was built for this project because the environment it was developed in did not have network access to download a real public salary dataset. The generator encodes realistic, documented relationships between salary and features such as job title, education, experience, location, industry, company size, and skills, plus injected missing values, duplicates, and outliers so the cleaning pipeline has real work to do.

This is **not** real-world survey data and should not be treated as a market benchmark. If you have access to a real public dataset (for example, a Kaggle "Salary Data" style dataset with similar columns), you can replace `data/employee_salary.csv` with it and re-run `train_model.py` — the preprocessing pipeline expects the columns described in section 6.

To regenerate the synthetic dataset:

```
python data/generate_dataset.py
```

## 7. How to Train the Model

```
python train_model.py
```

This script will:

1. Load `data/employee_salary.csv`
2. Clean the data (duplicates, invalid values, outliers)
3. Engineer skill indicator columns
4. Build a `ColumnTransformer` + `Pipeline` for preprocessing
5. Train four regression models: Linear Regression, Decision Tree, Random Forest, Gradient Boosting
6. Evaluate each with MAE, MSE, RMSE, and R² on a held-out test split
7. Select the best model by test R²
8. Save the full preprocessing + model pipeline to `models/salary_prediction_model.pkl`
9. Save evaluation metrics and model-derived feature importances to `models/model_metrics.json`

To regenerate the exploratory charts used on the About page:

```
python analyze_dataset.py
```


## 9. Machine Learning Algorithms Used

- **Linear Regression** — baseline linear model
- **Decision Tree Regressor** — single tree, captures non-linear splits
- **Random Forest Regressor** — ensemble of trees, reduces variance
- **Gradient Boosting Regressor** — sequential boosted trees, typically strongest on tabular data

All four are trained and compared on every run of `train_model.py`; the one with the highest R² on the held-out test set is automatically selected and saved for use by the web app.

## 10. Evaluation Metrics

- **MAE** (Mean Absolute Error) — average absolute prediction error, in the same currency units as salary
- **MSE** (Mean Squared Error) — average squared error, penalizes large misses more heavily
- **RMSE** (Root Mean Squared Error) — square root of MSE, back in currency units; used to build the displayed salary range
- **R² Score** — proportion of variance in salary explained by the model

The exact figures from the most recent training run are shown on the in-app About page (`/about`) and in `models/model_metrics.json`, not hardcoded anywhere in the templates.

## 11. Salary Range and Confidence Methodology

- **Range**: `predicted_salary ± RMSE` of the selected model on its held-out test set. This is a transparent, documented statistical margin — not a promise about any specific job offer.
- **Confidence label**: derived from the selected model's test R² — "High" for R² ≥ 0.90, "Moderate" for R² ≥ 0.75, otherwise "Indicative."
- **What influenced your prediction**: computed from the trained model's own coefficients (linear models) or feature importances (tree-based models), aggregated back to the original input categories. These are real, model-derived weights, not guesses.
- **Salary comparison**: the "average for similar profile" figure is the mean salary for the same job title within this project's own cleaned dataset, explicitly labeled as a dataset-based estimate rather than an external market survey.
- **Suggestions**: generated by simple, transparent rules in `utils/recommendations.py` (skill gaps against a documented high-value skill list, experience/education bracket observations) — there is no LLM or external AI involved.

## 13. Security Notes

- Passwords are hashed with Werkzeug's `generate_password_hash` / `check_password_hash` — plain-text passwords are never stored.
- Authentication is session-based; dashboard, prediction, history, and profile routes are protected with a `login_required` decorator.
- Prediction history is scoped to `user_id` at the database query level, so users can only ever see or delete their own records.
- All database access uses parameterized queries (no string-built SQL), which prevents SQL injection.
- Server errors are caught by custom error handlers so raw stack traces are never shown to end users.

## 14. Troubleshooting

**`InconsistentVersionWarning` when starting the app**
This means the scikit-learn version installed in your environment doesn't match the version that originally trained `models/salary_prediction_model.pkl`. It is usually harmless, but to remove it cleanly:

1. Make sure you installed dependencies inside the project's own virtual environment (`pip install -r requirements.txt`), not into a shared/base Anaconda environment that may already have a different scikit-learn version.
2. If the warning persists (for example, your platform can't install the exact pinned version), simply retrain the model against whatever scikit-learn version you do have installed:
   ```
   python train_model.py
   ```
   This regenerates `models/salary_prediction_model.pkl` and `models/model_metrics.json` using your local library versions, so the saved pipeline always matches the environment running it.

## 18. Deploying on Render

This project is configured for deployment on Render.

- Root directory: `employee_salary_prediction`
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn app:app`
- Set `SALARYSENSE_SECRET_KEY` as an environment variable (Render can generate one automatically).

Note: SQLite storage on a free/ephemeral hosting service is suitable for a demo, but user accounts and prediction history may be reset when the service is redeployed or its instance is replaced. The trained model and CSV dataset are included in the repository and do not depend on the SQLite database.
